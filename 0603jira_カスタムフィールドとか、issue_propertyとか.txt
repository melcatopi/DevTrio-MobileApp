Issue Properties って何？
課題(Issue)1個1個に対して、好きなキーで好きなJSONをくっつけられる保管庫みたいなやつ。カスタムフィールドと違ってUIには一切出ないし、スクリーン設定もいらない。必要な権限は普通の Edit Issue 権限だけだから、管理者じゃなくても読み書きできるの。今回みたいな「APIで触る内部フラグ」には理想的🙆‍♀️

エンドポイントは3つだけ
PUT     /rest/api/3/issue/{issueIdOrKey}/properties/{propertyKey}   # 保存(=作成も更新も同じ)
GET     /rest/api/3/issue/{issueIdOrKey}/properties/{propertyKey}   # 読み取り
DELETE  /rest/api/3/issue/{issueIdOrKey}/properties/{propertyKey}   # 削除
propertyKey は自分で好きに決めるキー名（例：my-checkbox）。中身のJSONも自由。

チェックのON/OFFをやる
中身は何でもいいけど、シンプルにこんなJSONにしとく：

json
{ "checked": true }
チェックを入れる（保存）

PUT /rest/api/3/issue/PROJ-123/properties/my-checkbox
Body: { "checked": true }
チェックを外す

PUT /rest/api/3/issue/PROJ-123/properties/my-checkbox
Body: { "checked": false }
PUTは作成も更新も同じだから、「すでにあるか」を気にしなくていいのがラク。成功すると新規作成で 201、更新で 200 が返る。

Pythonで書くとこう
python
import requests

domain = "https://your-domain.atlassian.net"
issue_key = "PROJ-123"
prop_key = "my-checkbox"
auth = ("your-email@example.com", "API_TOKEN")

def set_checkbox(issue_key, checked: bool):
    url = f"{domain}/rest/api/3/issue/{issue_key}/properties/{prop_key}"
    res = requests.put(url, json={"checked": checked}, auth=auth)
    print(res.status_code)  # 201(新規) or 200(更新)
    return res

def get_checkbox(issue_key) -> bool:
    url = f"{domain}/rest/api/3/issue/{issue_key}/properties/{prop_key}"
    res = requests.get(url, auth=auth)
    if res.status_code == 404:
        return False  # まだ一度も設定されてない＝未チェック扱い
    return res.json()["value"]["checked"]

def toggle_checkbox(issue_key):
    current = get_checkbox(issue_key)
    set_checkbox(issue_key, not current)
    print(f"{current} → {not current}")

# 使い方
set_checkbox(issue_key, True)    # 入れる
set_checkbox(issue_key, False)   # 外す
print(get_checkbox(issue_key))   # 読む
toggle_checkbox(issue_key)       # トグル

groovy
import com.atlassian.jira.component.ComponentAccessor
import com.atlassian.jira.entity.property.JsonEntityPropertyManager
import groovy.json.JsonSlurper
import com.onresolve.scriptrunner.runner.rest.common.CustomEndpointDelegate
import groovy.transform.BaseScript
import javax.ws.rs.core.Response

@BaseScript CustomEndpointDelegate delegate

notifyCheck(httpMethod: "POST") { MultivaluedMap queryParams, String body ->
    def payload = new JsonSlurper().parseText(body)
    def commentId = payload.commentId as Long

    def propMgr = ComponentAccessor.getComponent(JsonEntityPropertyManager)
    def entityProperty = propMgr.get("CommentProperty", commentId, "notifyteams")

    if (entityProperty == null) {
        return Response.ok('{"notified": false, "reason": "no property"}').build()
    }

    def value = new JsonSlurper().parseText(entityProperty.value)
    if (value.notify == true) {
        // Teams通知処理
        return Response.ok('{"notified": true}').build()
    }
    return Response.ok('{"notified": false}').build()
}

python
import requests

domain = "https://kari.rickcloud.jp/jira"
auth = ("...", "...")          # コメント投稿で通った認証そのまま
PROP_KEY = "notifyteams"

def post_and_trigger(issue_key, body_text):
    # ① コメント投稿
    url = f"{domain}/rest/api/2/issue/{issue_key}/comment"
    res = requests.post(url, json={"body": body_text}, auth=auth)
    res.raise_for_status()
    comment_id = res.json()["id"]

    # ② Issueプロパティに書く ← これが発火トリガー
    prop_url = f"{domain}/rest/api/2/issue/{issue_key}/properties/{PROP_KEY}"
    payload = {"notify": True, "commentId": comment_id}
    requests.put(prop_url, json=payload, auth=auth).raise_for_status()

    return comment_id

post_and_trigger("TESTISSUE-119", "通知対象のコメントです")
